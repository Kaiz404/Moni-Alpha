# @repo/core

Pure domain rules the phone app and the web app share. Raw TypeScript, no build step: Metro reads it directly, and Next.js through `transpilePackages`.

| Module | What it answers |
| --- | --- |
| `ai-consent.ts` | The user's choice about Moni's AI from the `ai_consent_current` rows (`consentFromRows`), whether a use may run (`aiUseAllowed`), and what Turn on and Not now record. |
| `calendar.ts` | `createCalendar(zone)` reads an instant as a day key, a month key or a day number in one IANA zone, and finds when a day starts. Day and month arithmetic (`addDays`, `daysBetween`, `daysInMonth`, `shiftMonth`, `addMonths`) needs no zone. |
| `glossary.ts` | The words `docs/redesign/glossary.md` fixes: money (`RM1,116.20`, U+2212, whole ringgit for forward-looking numbers), day labels, due phrases, month names and chart ticks. Every date word takes day keys. |
| `ledger.ts` | What a row means: whether a transaction counts as spending, as income or as cash flow, whether it is filed, and what it does to a wallet's balance; a debt's totals, its stored status, and its state on a day (open, due soon, overdue, settled, written off). |
| `chart-range.ts` | The chart ranges (1M, 7D, 30D, 90D, 1Y, All) and where each starts. |
| `money-month/` | One user's month of money: `moneyLedger` reads the synced rows once (the user's categories, budgets, monthly total and this month's bills from `detectRecurring` and the overrides), and `buildMoneyMonth` answers any month: spend per day, even pace and the days at or under it (`evenPace`, one rounding), bills and debts due, what is left and safe to spend a day (`safePerDay`), per-category spend, and the sentences each screen shows (`words.ts`). `nextDays` lists the bills and debts due in Home's next 14 days. Bills, recurring series and the calendar heat live here too, and `spendByMonth` with `lastMonthAndAverage`: each category's spending over the months before one, for Budget's last month and 3-month average columns and its category history. |
| `write-plans/` | Ledger commands as plans: each returns the rows to insert, patch and soft-delete (`RowWrites`), or why nothing can be written (`needsInput`, `error`), and writes nothing itself. Transactions and bulk edits, the one transfer rule (`checkTransfer`), balance correction, category budgets (`planCategoryBudget`, which revives a soft-deleted row since the table key keeps it, and `budgetsFromSpending`), debts with their cash mirrors and status (and `planDebtEdit` for its own fields, `planDebtDelete` for a whole debt), wallet deletion with its transactions, and import rows without gated columns. Plans read a `LedgerView` (the read model's live wallets, transactions, debts and activities) and a `PlanContext` (user, now, new ids, which gated columns exist). `applyToTables` is the in-memory applier. Review decisions start here (`review.ts`: `planApprove`, `planCaptureWallet`, how familiar a merchant is, the captures Approve all usual takes, the bank alert a notification capture keeps with `captureAlert` and `alertKey`), the check-in's answer (`planCheckIn`), Add a place (`planAddPlace`, which pins expenses to one of the user's places), and `undoWrites`, the writes that put a plan's rows back for a toast's Undo. |
| `charts/` | `month-charts.ts`: the web's month charts laid out for any box: Pace and Daily (`paceChart`, `dailyChart`), Activity's running totals against last month (`runningChart`), the 1M ticks with Today, and `nearestDay` for a pointer. |
| `read-model/` | The finance read model: synced rows as finance types (`rows.ts`), the projection with transactions by wallet and activities by debt (`projectFinance`), and what the screens read from it: wallet balances, net worth, budget progress, category spend (`selections.ts`), merchants, places (`places.ts`: grouping, ranges, the wallet filter, the expenses without a place, the days of a range and a place's spending by day), the map maths both maps share (`place-map.ts`: `clusterPins` merges pins that touch, `fitProjector` lays coordinates into a box for the web's drawn map, `regionFor` and `projector` for the phone's), Activity's filter and chart series, a See all list's scope (`list-scope.ts`), spend and balance history, the Debts summary and the month report. A transaction's row (`transactionRow`, `compactWalletNames`), the check-in's wallet (`walletToCheckIn`), and the recurring verdicts and merchant names from their synced rows (`user-rows.ts`). |

The zone is always a parameter. Mobile builds its calendar from the device zone (`apps/mobile/lib/dates/device-calendar.ts`); the web will build it from the profile zone.

```bash
pnpm --filter @repo/core test         # Vitest
pnpm --filter @repo/core check-types
pnpm --filter @repo/core lint
```
