# Web app: architecture and build plan

How the web app shares logic with the phone app, what is written twice, and the order of work. The design and its rules are in [`../WEB.md`](../WEB.md). The evidence behind each decision is in [`explore/`](explore/): domain logic (`explore-domain.md`), data, sync and auth (`explore-data.md`), UI (`explore-ui.md`) and tooling (`explore-tooling.md`), each with file and line references.

Vocabulary: a **module** has an **interface** (everything a caller must know) and an **implementation**. A module is **deep** when a lot of behaviour sits behind a small interface. A **seam** is where an interface lives, and an **adapter** fills it. A seam is real only when two adapters exist.

## Decisions

1. **Share logic, write views twice.** Domain rules, formatting, chart maths, tokens, the mascot and the data layer live in workspace packages. React views are written once in React Native (`apps/mobile`) and once for the DOM (`apps/web`). Components that look alike behave differently on desktop (segmented glide vs click, hold menu vs right-click, sheets vs popovers, rows with hover, checkboxes and J/K), so sharing them fails the deletion test.
2. **One Next.js app draws both web layouts.** The phone layout under 700 px is DOM views modelled on the mobile v2 screens, inside the same app, so crossing the breakpoint keeps the route, selection and half-typed fields. React Native Web and an Expo web build were rejected for this reason.
3. **Rebuild `apps/web`.** Keep only the `@supabase/ssr` browser, server and cookie-refresh clients and the auth callback (about 120 lines). Delete the 12 API routes: each has one caller, RLS already does their auth work, and they hard-delete transactions (mobile sync never sees the delete), sum across currencies and overwrite preferences.
4. **The web talks to Supabase directly with RLS**, as mobile does. Secret-key operations (account deletion, QR sign-in) are Supabase Edge Functions that both apps call. The Go AI gateway gets a CORS allowlist for the web origin, so both apps share one AI client.
5. **No server rendering of ledger data.** The landing page, auth and the app shell render on the server; the ledger loads into the browser (bills, routine detection, duplicates, budgets and import dedupe run over the full history).
6. **Data layer: Option C (owner's decision, 19 Nov 2026).** Share the Legend-State store through `createMoniStore({ supabase, persist })`. Persistence (MMKV on the phone, IndexedDB or memory on the web) and the Supabase client (MMKV auth storage on the phone, `@supabase/ssr` cookies on the web) are the two real adapters. Option B (shared rules only, with a separate TanStack Query cache on the web) was rejected because it rebuilds incremental sync a second time.

## Packages

All packages export raw TypeScript (as `@repo/types` does today): Metro consumes them with no extra config, and Next.js through `transpilePackages`. Shared code compiles under both apps' TypeScript versions and uses a `shared.json` tsconfig without the DOM library, so a browser-only API can't slip into code the phone runs.

| Package | Holds | Comes from |
| --- | --- | --- |
| `@repo/types` (exists) | Zod schemas; database types generated by `supabase gen types` (replacing the web's stale copy and mobile's 22 hand-written row types); the AI wire contract as Zod schemas; a golden JSON fixture the Go tests also read | `packages/types`, `lib/ai/client/types.ts`, `lib/ai/notification-types.ts` |
| `@repo/core` | Pure domain modules (below) with their tests | about 9,000 pure lines of `apps/mobile/lib` (`finance`, `dates`, `reports`, `places` grouping, `ai/facts`, `ai/insights`, `ai/snapshot`, merchant names, chart ticks and geometry) |
| `@repo/data` | Supabase row gateway (create or revive, update, paged list, soft delete), write-plan applier, and `createMoniStore` (Option C) | `apps/mobile/lib/store`, `lib/supabase/*.ts` |
| `@repo/ai` | AI client created with a base URL, a token getter and an image encoder; always returns ok, skipped or unavailable | `lib/ai/client/http-client.ts`, `lib/places/client.ts` |

## Deep modules inside `@repo/core`

1. **Calendar and glossary.** A calendar created with an explicit IANA timezone answers day and month keys, days between, days in a month. A glossary formats money (`RM1,116.20`, U+2212 for expenses, whole ringgit for forward-looking numbers), day labels, due phrases and chart ticks. Mobile passes the device zone, web the profile zone. Replaces four date conventions, four month-name arrays and about six helpers.
2. **Ledger rules.** Named questions about a transaction (counts as spending, as income, as cash flow, is filed, effect on a wallet's balance) and about a debt (balance and state on a day). Replaces about ten hand-written predicates that disagree today: Budget excludes debt repayments and other currencies, while Moni chat's snapshot (`lib/ai/snapshot/finance-metrics.ts:82`) and the answer card (`components/chat/answer-card.tsx:47`) count debt repayments.
3. **Money month.** Raw rows, now and the main currency in; the whole month out: spent and series, budget and even pace at one rounding, bills and debts due, left and safe per day, per-category spend, and the ready glossary sentences. Callers never filter or round. Bills come from recurring detection, so that moved with it (`money-month/recurring.ts`, also read by Moni chat's facts).
4. **Read model.** Rows in (any order, soft-deleted included), a normalised projection out, with pure selections: wallet balances, net worth by currency, the activity list for a scope and filter, the month report, places, merchants, debts. Mobile's Legend `computed` selectors become a thin caching adapter.
5. **Write plans.** Commands return the rows to insert, patch and soft-delete (or "needs input", or an error) instead of writing. Platform side effects (capture status, linked packages, receipt queues, events) leave the commands and run in the mobile adapter. Covers balance correction, transfers, debt mirroring, wallet deletion, import apply and bulk edits.
6. **Review decisions** (build with the web Review page, when the second adapter exists): a proposal, the ledger and a decision in; the changes and the capture status out.

## Build order

Each phase ends in a verifiable state. Mobile must behave the same after every phase: run its jest suites, and prove screens that could change on the device with the `moni-device` skill. Callers move to the new module and the old copies are deleted in the same change; no compatibility layers.

0. **Subtract and set up.** Delete the old web app except the kept files. Pin web React to 19.2.3 (mobile's version) so a shared package never loads two copies of React. Add `packages/typescript-config/shared.json`. Add Vitest for packages and web, and a web `build` to CI (`.github/workflows/ci.yml`). Generate database types into `@repo/types`; drop the dead analytics schemas; export every file. (Done. The 22 hand-written mobile row types move to the generated ones with the store in phase 4, when `lib/supabase/*.ts` moves.) Fix or drop the `wallet_balances` view, which counts soft-deleted transactions.
1. **`@repo/core`: calendar and glossary, then ledger rules.** Migrate every mobile caller and delete the duplicates. This fixes Moni chat counting debt repayments as spending; add a test for it.
2. **`@repo/core`: money month and read model.** Mobile's selectors become thin adapters; the finance test suites move with the code.
3. **`@repo/design` and `@repo/brand`.** Mobile's `global.css` and brand assets become generated output with no visual change (compare device screenshots before and after). (Done. The spring curves come from the W2-Motion board's simulation, so their durations are its settle times, 231 to 818 ms, not the hand-saved `curves.txt` and the 272 to 840 ms the boards quote. The phone's Python asset generator reads `@repo/brand` through `packages/brand/python/catart.py`; the canvas kit's own `catart.py` copy outside the repo can switch to that bridge. The wordmark and lockups stay HTML, because the word is live text.)
4. **`@repo/data` and write plans.** Mobile runs on the shared store (`createMoniStore`). Edge Function `delete-account` and the in-app deletion (issue #56). (The functions `delete-account`, `qr-start`, `qr-approve` and `qr-poll` landed early, 19 Nov 2026; the contract is in `docs/ARCHITECTURE.md` § Auth.)
5. **`@repo/ai`.** The wire contract as Zod plus the golden fixture tested from TypeScript and Go. Zero data retention on the gateway (issue #55) and the AI consent gate (issue #57: a custom access-token hook adds a consent claim; the gateway checks it).
6. **Web shell.** Next.js app, tokens, Funnel Display, auth (email, Google, QR sign-in through the Edge Functions `qr-start` and `qr-poll`, then `verifyOtp`), the sidebar, rail and phone layouts with the breakpoint switch, Ctrl K, toasts, motion. (Done. The `web-verify` skill drives every route at four widths in both themes; `apps/web/README.md` describes the shell.)
7. **Web screens**, in this order: Home, Activity, Review (with review decisions), Budget, Debts, Where you spend, Moni chat, Settings and data (import, merchant names, rules, capture sources).
8. **Edges.** Landing page and the public deletion page, onboarding, states and empty states, the phone layout for every screen, privacy policy and terms pages.

## Testing

- Shared packages: Vitest, run by the existing CI `pnpm test` job. Tests call each module's interface with literal inputs and assert literal outputs; the timezone is a parameter, not a process setting.
- Mobile: its jest suites keep running; moved suites run under Vitest in their package.
- Web: Vitest for its own modules, and Playwright driving the real app for each screen, comparing against the board renders in `~/.local/share/moni-canvas/web-r1/renders/`. The `web-verify` skill (`.claude/skills/web-verify/`) runs it; each screen phase extends its drive.
- The AI contract: one golden JSON fixture parsed by Zod in TypeScript and unmarshalled with `DisallowUnknownFields` in Go.
