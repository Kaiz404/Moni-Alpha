# Moni web app

Next.js 16 App Router app with the same features as the phone app plus desktop-only ones. It is being rebuilt to the locked design: the handoff is [`docs/WEB.md`](../../docs/WEB.md) and the architecture and build order are [`docs/web/PLAN.md`](../../docs/web/PLAN.md).

## Develop

```bash
pnpm --filter web dev     # http://localhost:3000
pnpm --filter web test    # Vitest
pnpm --filter web build
pnpm --filter web verify  # Playwright drive: every route, width and theme; last line PASS or FAIL
```

Env: copy `.env.example` to `.env` (Supabase URL, publishable key, and the phone app's URL scheme for the sign-in QR). The verify drive needs Chromium once (`npx playwright install chromium`) and reads the dev project's keys from `apps/mobile/.env.e2e`; see `.claude/skills/web-verify/SKILL.md`.

## Structure

- `src/proxy.ts`: refreshes the Supabase cookie session on every request, sends signed-out visitors on private paths to `/login?next=…`, and sends signed-in visitors on the sign-in pages to the app (the landing page stays, with Open Moni). The path lists are in `src/lib/routes.ts`.
- `src/lib/supabase/`: `client.ts` (browser) and `server.ts` (Server Components and route handlers), both typed with `@repo/types/database`.
- `src/app/auth/callback/route.ts`: the PKCE code exchange for Google sign-in and email links.
- `src/app/layout.tsx`: `@repo/design/tokens.css`, Funnel Display from `public/fonts/` (declared in `globals.css`; the build Google serves Chrome on Windows and Linux, which the boards render with, not the Mac build `next/font/google` fetches, which sets text about 5% wider), and two inline scripts that run before paint: the theme (`src/lib/theme.ts`, stored in `localStorage` as on the phone, light by default) and the layout (`src/lib/layout.ts`).
- `src/app/(auth)/login/…`: sign in and create account (one page, `?mode=create`), `forgot`, `verify` and `reset`, in `src/components/auth/`. Create account checks the 18+ rule with `@repo/types`. The QR panel (`qr-panel.tsx`, `src/lib/qr-sign-in.ts`) calls the `qr-start` and `qr-poll` Edge Functions, rotates the code, and finishes with `verifyOtp`.
- `src/app/delete-account/` and Settings › Profile's `DeleteAccountDialog`: Delete your account (issues #56 and #74), a public page for the Play listing and a confirm dialog in the app, both on `src/components/account/delete-account-form.tsx`. Signed out, the public page emails a sign-in link back to itself (`shouldCreateUser: false`, the same answer either way). The form calls the `delete-account` Edge Function with the browser's access token (`src/lib/account-functions.ts`, parsed with `@repo/types`), then `signOut` from `shell-store.ts`, the one sign-out path, and leaves for `/delete-account/done`. Export data first (`src/components/account/export-data-button.tsx`) downloads the Moni export once the store has pulled; signed in, the public page mounts `StoreSync` for it.
- `src/app/(marketing)/`: the public site, statically rendered outside the shell. `/` is W2-LandingFinal (`src/components/marketing/`): `page.tsx` composes the sections (`landing-hero`, `landing-bento`, `landing-map`, `landing-privacy`, `landing-faq`) with the closing and footer; `site-header.tsx` reads the browser session after load and swaps Sign in for Open Moni. Each animated visual is a `Moment` (`moment.tsx`): its markup rests at the end state, it plays once when scrolled into view, and Replay remounts it. `/privacy` and `/terms` (`/privacy/ms`, `/terms/ms` in Malay) render `src/components/legal/` documents through `legal-page.tsx`, which adds the language switch, the contents and, while `LEGAL_REVIEWED` is false, "Draft, not yet reviewed". Every fact the owner has to confirm (data region, price, launch countries, tested banking apps, support email, domain, legal entity, Google Play link, postal address, the AI providers' retention, the effective date, governing law) is in `src/lib/site-facts.ts`; until confirmed, `<Fact>` (`components/marketing/fact.tsx`) shows it as a marked "[CONFIRM: …]".
- `src/lib/moni-store.ts` and `src/components/store/store-sync.tsx`: the shared Legend-State store (`@repo/data`'s `createMoniStore`) on the browser client with `memoryPersist()`, one per tab. `StoreSync`, mounted in the `(app)` layout, observes every table and pulls the ledger once a session exists; `signOut` in `shell-store.ts` runs `signOutEverywhere`, which clears the store before ending the session. Screens read it through `useLedger` (`src/lib/ledger/use-ledger.ts`): the tables copied out of the store, `projectFinance`, the money month and the waiting captures, with a clock that starts after hydration so the server's HTML always matches. Writes go through `commit` (`src/lib/ledger/commit.ts`): a `@repo/core` write plan applied with `applyWrites`, then a toast whose Undo (and Ctrl Z) applies `undoWrites` from a snapshot of the rows it touched, or, when undoing is a plan of its own (a repayment, a new debt, a budget), runs that plan through `applyPlan` against the store as it is then (`budgetRowsNow`, `ledgerViewNow`). `src/lib/__tests__/moni-store.live.test.ts` pulls the web e2e user's wallets from the dev project (skipped without `apps/mobile/.env.e2e`).
- `src/app/(app)/…`: the signed-in app. Its layout reads the profile on the server (name, main currency, finance timezone) and renders `Shell` (`src/components/shell/`). Sections without a screen yet show their title and W2-Empty empty state.
- Home (`src/components/home/`): `home-screen.tsx` places the cards in fixed slots that Customise swaps (drag, or arrow keys on a grip) and hides; the layout is per browser in `localStorage` (`src/lib/home-layout.ts`) and the phone layout reads the same order. `spent-card.tsx` draws `@repo/core`'s `paceChart` and `dailyChart` at the measured size with a pointer tooltip (P and D switch); `review-card.tsx` approves with `planReview` (`reviewContext` and `reviewView` in `src/lib/ledger/commit.ts`); `side-cards.tsx` holds Next 14 days (`nextDays`), Wallets with the check-in (`walletToCheckIn`, `planCheckIn`) and Where you spend, a Maps Static API image (`staticFrame`, `staticMapUrl` in `src/lib/google-maps.ts`, `miniMapStyles` from `@repo/design`) with this month's three biggest places (`groupPlaces`) pinned on top; the tile opens the map.
- Activity (`src/components/activity/`): one `ActivityScreen` mounted by `app/(app)/activity/layout.tsx`, so `/activity/<id>` opens the detail pane without remounting the list. The view, filters, sort and page are URL parameters (`src/lib/activity-query.ts`, which also filters, sorts and pages); saved views are per browser in `localStorage`. Bulk edits use `planTransactionsEdit` and `planTransactionsDelete`; screen keys go through `useScreenKeys` (`src/lib/screen-keys.ts`), which rests while typing or while an overlay or pane is open, and reuses `keyStep` so G then a letter stays Go to.
- Budget (`src/components/budget/`) and Debts (`src/components/debts/`) read `useLedger` too and share `src/components/ledger/`: the tables (`table-pane.css`) on top of `ledger.css`'s cards and rows, the URL state (`use-query-param.ts`: `?month`, `?view`, `?category`, `?person`, `?side`, `?record`) and the glyphs, bubbles and person tiles (`glyph.tsx`). Pure view logic with tests is in `src/lib/budget-view.ts` and `src/lib/debts-view.ts`. Every write is a plan (`planCategoryBudgets`, `planDebt`, `planDebtActivity`).
- Review (`src/components/review/`, route `/review`, the capture in `?capture=` and Recently reviewed in `?view=recent`): `review-screen.tsx` orders the inbox with `inboxOrder`, keeps ticks, edits and "Don't ask about similar" per capture in its state, and decides through `@repo/core`'s `planReview` with `combine` for bulk, so the toast's Undo and Ctrl Z apply `planReopen` for each; keys J, K, Space, A, X, Esc. `capture-pane.tsx` is one element for every layout: docked right of the 440 inbox on the sidebar and rail (the page keeps the inbox's width), over the list on the one-column rail, the deck's one card on the phone layout. It shows the source (the alert quoted, the chat line, the receipt photo through a signed link from `src/lib/receipt-photo.ts` over `@repo/data`'s `receiptPhotos`), the fields as listbox popovers, and the rule preview (`similarMatches`) or the merchant's month (`merchantHistory`). `review-done.tsx` is All caught up and Recently reviewed (`ledger.reviewed`, with Move back to Review). The words are `src/lib/review-view.ts`.
- Wallets (`src/components/wallets/`, routes `app/(app)/home/wallets/` and `home/wallets/[id]/`, pushed from Home's Wallets card): `wallets-screen.tsx` groups with `walletGroups` and names rows with `walletListMeta` (both `@repo/core`, shared with the phone), adds This month (`monthChanges`), the assets and owed split and Download CSV (`src/lib/wallets-view.ts`); `wallet-screen.tsx` edits the amount with `planCheckIn`, saves Edit wallet with `planWalletEdit` and deletes with `planWalletDelete`; `balance-card.tsx` draws `balanceChart` over `balanceIndex`; `wallet-form.tsx` is New wallet and Edit wallet in the `SidePane`, its types and colours from `WALLET_TYPES` and `WALLET_COLOURS`.
- Where you spend (`src/components/places/`, route `app/(app)/home/places/`, pushed from Home's card, so Home stays lit and the phone layout shows Back and no tab bar): `place-map.tsx` draws a pin per place at `fitFrame`'s spot over `map-ground.tsx`, a Google map (Maps JavaScript API, loaded once by `loadMaps`, styled with `@repo/design`'s `mapStyles`) that takes no gestures: its camera follows the same frame (`unproject`, `googleZoom`), so the pins sit on their streets. + and − zoom and Fit (F) change the view (`toView`, `zoomView`, `panView` in `src/lib/places-view.ts`), which slides camera and pins together on the sheet spring, and `clusterPins` merges pins that touch at the current zoom. A drag pans once zoomed. Without `NEXT_PUBLIC_GOOGLE_MAPS_API_KEY`, or when Google refuses it, the ground is Sand with Map unavailable. The range, category, wallet, Pins | Heat, Spent | Visits and the open place are URL parameters (`readPlacesQuery`). `place-side.tsx` swaps the places list for the place pane (visits by day from `placeByDay`, what you bought, payments, Open in Google Maps); `day-grid.tsx` is Day by day; `without-place.tsx` lists `unplacedExpenses` and pins ticked ones with `planAddPlace` through `commit`, so its toast's Undo and Ctrl Z put them back. Keys: J, K, H, F, P, Esc.
- Moni chat (`src/components/chat/`): `chat-pane.tsx` is the pane the shell mounts on `?pane=chat` (the pushed page under 700 wide): the header with the AI label and "Looking at …" (`lookingAt` in `src/lib/chat-thread.ts`, from the route, Activity's URL and its ticked rows, which live in `shell-store.ts`), W2-Empty's first open, the thread and the box. The thread and the half-typed message are in `shell-store.ts`, so a resize or a section change keeps them. `ask.ts` handles a message: a request to move rows becomes a draft from `@repo/core`'s `draftCategoryChange` over the rows in view (`rowsInView` in `src/lib/activity-items.ts`) with no AI call; a spend points to Add; a question waits on `consent-dialog.tsx` while chat's AI is off, then goes through `webAiClient('chat')` with `buildChatSnapshot`, the phone's history (`historyForApi`) and the tone, and answers with `pickViewAnswerCard`'s card (`answer-card.tsx`, the category or month by week from `spendByWeek`, the bills, the captures) captioned by the reply. `draft-card.tsx` approves with `planTransactionsEdit` through `commit`, whose Undo the card and Ctrl Z share; `draft-marks.ts` lights the same rows in Activity behind.
- Settings (`src/components/settings/`, `app/(app)/settings/layout.tsx`): `SettingsFrame` draws the section nav from `src/lib/settings-nav.ts` beside each section; under 700 wide `/settings` is the phone's Profile rows and each section a pushed page (`Page`'s `phoneTitle`). Profile writes Moni's tone with `updateProfilePreferences`; Moni's AI uses `useAiConsent` and `changeAiConsent` (`src/lib/ai.ts`). Merchant names lists `merchantNameList` (`src/lib/merchant-names-view.ts`: filter, search, sort, 25 a page) and writes through `planMerchantNames` and `planForgetMerchantNames` with `commit`. Import and export (`import-section.tsx`) reads a file with `readImportFile`, previews with `previewRows`, plans with `planImport` over `readStoreSnapshot` once `storeHasPulled`, writes with `applyPlan`, and its Undo soft-deletes exactly the rows written (`src/lib/import-flow.ts`). CSV matching and ticks are desktop only.
- The docked detail pane is one component, `SidePane` (`src/components/ledger/side-pane.tsx`), for Activity's transaction, Budget's category and Debts' person: docked on the sidebar and on the rail from 1240 wide (the page makes room), over the page with a scrim below that, the pushed page on the phone layout. `idle` keeps it docked with a placeholder while nothing is open (Budget, and Debts once there is somebody).
- Set-up (`src/app/welcome/`, `src/components/setup/`, words and rules in `src/lib/setup.ts`): Home's page sends a brand-new account there (`needsSetup` from `@repo/data`), and `/welcome` sends anyone else home. The four steps keep their choices in a reducer; Moni's AI records at once with `changeAiConsent`, and Finish writes the wallets with `planWalletCreate`, waits for them to sync, then saves the main currency and `setup_finished_at`. Home's Get set up card (`components/home/setup-card.tsx`) shows in the Review slot from then until every step is done or it is closed (`setup_checklist_hidden`).
- States (`src/components/states/`): `FullPage` for `app/not-found.tsx`, `app/error.tsx` and `/maintenance` (the proxy rewrites every other page there while `MONI_MAINTENANCE_UNTIL` is set); `connection.tsx` for the offline banner `Page` draws under its header, `useOnline` and the back-online toast; `session-dialog.tsx` for Sign in again when the session ends without Sign out. First-load blocks are `LoadingCard` on Home and block rows on Activity, still and only after 300 ms. A Home card whose table failed to pull is `CardError`. Toasts (`shell-store.ts`) come in four tones (done, undone, error, info), and Ctrl Z undoes the latest change after its toast has gone.
- `src/lib/glyphs.generated.ts`: MDI paths for icons rows name as data (categories, wallets), from `scripts/gen-glyphs.mjs`.

## The shell

- **One tree for every layout.** `src/lib/layout.ts` holds the breakpoints (phone under 700 wide or 500 tall, rail with one column to 1024, rail to 1360, sidebar beyond). It generates the media queries that show the sidebar, rail or tab bar (`data-only="…"`) and the script that sets `<html data-layout>`. Nothing remounts when the layout changes, so a half-typed field survives.
- **Where you are lives in the URL**: the route, and `?pane=chat|add` for the docked Moni chat and the Add drawer. Drafts and the open overlay live in `shell-store.ts`, as do toasts (one at a time; the Mint bar's end closes it, so pointing at it pauses both).
- **One list of places** (`src/lib/nav.ts`) feeds the sidebar, rail, tab bar, Ctrl K palette (`src/lib/commands.ts`), the G-then-letter keys and the shortcuts dialog (`src/lib/keys.ts`). Keys: Ctrl K, /, N, ?, Esc, Ctrl Z, G then H A B D R S. They rest while you type, except Ctrl K and Esc.
- **Motion** uses the shared spring curves (`--ease-*`, `--duration-*` from `tokens.css`); under `prefers-reduced-motion` panes and dialogs fade. The theme switch opens as a circle through view transitions.
- **Brand**: `src/components/brand.tsx` inlines `@repo/brand`'s SVG and wordmark strings. A page cat is drawn twice (Deep mint and Paper) and CSS shows the one for the theme. Icons are `@mdi/js` paths by the phone's kebab names (`src/lib/icons.ts`).

The web reads and writes Supabase directly under RLS, as the phone does, and never hard-deletes a synced row. Shared logic comes from workspace packages listed in `next.config.js` `transpilePackages`.
